# التشغيل والنشر

## متغيرات البيئة

| المتغير | مطلوب | الوصف |
| --- | --- | --- |
| `TELEGRAM_TOKEN` | نعم | توكن بوت المبيعات من BotFather |
| `MANAGER_IDS` | نعم للتشغيل الفعلي | معرّفات المديرين مفصولة بفاصلة (محمد ومصطفى) |
| `INGEST_TOKEN` | نعم لاستقبال الطلبات | رمز سري طويل، نفسه في بوت العميل |
| `DB_PATH` | لا | الافتراضي `/data/sales.db` |
| `ASSIGN_MODE` | لا | `balanced` أو `manual` |
| `BRIEF_HOUR` | لا | ساعة ملخص الصباح، الافتراضي 8 |
| `WORK_DAYS` | لا | أيام العمل بترقيم بايثون، الافتراضي الأحد إلى الخميس: `6,0,1,2,3` |
| `ALERT_UNCONTACTED_HOURS` | لا | فارغ يعني بلا تنبيه. يحدد مصطفى عدد الساعات |
| `STOCK_STALE_HOURS` | لا | بعدها يظهر تحذير قدم المخزون، الافتراضي 48 |
| `PROTECT_CONTENT` | لا | الافتراضي 1: يمنع إعادة توجيه الرسائل وحفظها |
| `ODOO_URL` `ODOO_DB` `ODOO_LOGIN` `ODOO_API_KEY` | لا | الأربعة معاً لتفعيل القراءة من أودو |
| `STOCK_SOURCE` | لا | `file` أو `odoo` (تجريبي) |

## خطوات الإنشاء

1. من BotFather أنشئ بوتاً جديداً للمبيعات باسم وحساب منفصلين عن بوت العميل، وخذ التوكن
2. اختر الاسم بحيث لا يخطئ فيه العملاء، ولا تنشر رابطه في أي مكان عام
3. أنشئ التطبيق والـ volume:

```powershell
fly apps create marmo-sales
```

```powershell
fly volumes create sales_data --size 1 --app marmo-sales
```

4. ولّد رمزاً سرياً للاستقبال:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

5. اضبط الأسرار:

```powershell
fly secrets set TELEGRAM_TOKEN=التوكن INGEST_TOKEN=الرمز --app marmo-sales
```

6. انشر، ثم أرسل `/myid` للبوت لتعرف معرّفك، واطلب من مصطفى فعل الشيء نفسه:

```powershell
fly deploy --app marmo-sales
```

7. اضبط المديرين، وأعد التشغيل تلقائياً:

```powershell
fly secrets set MANAGER_IDS=معرّفك,معرّف_مصطفى --app marmo-sales
```

8. تأكد من جهاز واحد:

```powershell
fly scale count 1 --app marmo-sales
```

## ربط بوت العميل

بوت العميل يرسل كل طلب جديد لبوت المبيعات عبر الشبكة الداخلية في Fly، فلا يظهر الرابط للإنترنت:

```powershell
fly secrets set SALES_INGEST_URL=http://marmo-sales.internal:8080 SALES_INGEST_TOKEN=نفس_الرمز --app اسم-تطبيق-بوت-العميل
```

الطلبات السابقة للتفعيل لا تُحوَّل. إن فشل الإرسال تُعاد المحاولة كل 10 دقائق ولا يتكرر الطلب.

## أول استخدام

1. مصطفى: قائمة الفريق ثم إضافة عضو، بالصيغة `معرّف تيليجرام، الاسم، الفرع، أودو:رقم`
2. مصطفى: رفع المخزون ثم إرسال ملف Excel كمستند
3. مندوب: أرسل `/start`، واكتب اسم صنف، وافتح طلباً تجريبياً
4. أرسل طلباً من بوت العميل وتأكد أنه وصل المندوب

## ربط أودو

مستخدم أودو خاص بالبوت بصلاحية قراءة فقط، ومفتاح API. الربط مقفول حتى تُضبط المتغيرات الأربعة. يستخدم الواجهة xmlrpc المناسبة لأودو 17. لا يكتب البوت في أودو إطلاقاً.

## استكشاف الأعطال

| العرض | السبب المرجح | الحل |
| --- | --- | --- |
| `Conflict` في السجل | نسختان بنفس التوكن | `fly scale count 1` وأوقف أي تشغيل محلي |
| المندوب لا تصله الطلبات | لم يضغط `/start` أو غير مسجل | يضغط `/start` ثم يُضاف |
| بوت العميل لا يحوّل | الرمز مختلف أو العنوان خطأ | قارن `INGEST_TOKEN` و`SALES_INGEST_TOKEN` |
| لا ملخص صباحي | يوم إجازة أو الساعة لم تحن | راجع `WORK_DAYS` و`BRIEF_HOUR` |
| «تعذر قراءة الملف» | لا عمود كمية أو كود | أضف العمودين |
| الطلبات تضيع بعد النشر | لا volume | أنشئ `sales_data` |
